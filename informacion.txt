📦 Raíz del Proyecto
📄 package.json
Archivo principal del proyecto Node.
Contiene:
Dependencias (playwright, ajv, etc.)
Scripts de ejecución (npm run smoke)
Información del proyecto
Configuración básica del entorno Node
👉 Es el corazón del proyecto.

📄 package-lock.json
Archivo generado automáticamente.
Contiene:
Versiones exactas de dependencias instaladas
Garantiza que todos instalen exactamente lo mismo
👉 No se modifica manualmente.

📄 playwright.config.ts
Configuración global de Playwright.
Define:
Directorio de tests
Timeouts
Reintentos
Reporters
Proyectos (chromium, firefox)
Base URL
Configuración por entorno
👉 Controla cómo se ejecutan las pruebas.

📄 tsconfig.json
Configuración de TypeScript.
Define:
Versión de compilación
Soporte de módulos
Paths
Reglas de tipado
👉 Necesario si usas TypeScript.

📄 .env
Variables de entorno.
Ejemplo:
BASE_URL
DB_HOST
TOKEN
USER_ADMIN
👉 Permite cambiar entorno sin tocar código.

📄 .gitignore
Archivos que no deben subirse al repositorio.
Incluye:
node_modules
reportes
.env
archivos temporales

🧠 core/ — Componentes Compartidos
Contiene todo lo reutilizable entre dominios.
📁 core/config/
📄 environments.ts
Carga y centraliza variables del .env.
Ejemplo:
URLs por entorno
Configuración global
📄 constants.ts
Constantes globales del proyecto.
Ejemplo:
Timeouts estándar
Nombres de roles
Códigos esperados
📄 globalSetup.ts
Se ejecuta antes de la suite.
Puede:
Generar token global
Validar ambiente activo
Preparar configuración inicial

🌐 core/api/
📄 apiClient.ts
Cliente HTTP centralizado.
Responsable de:
Crear request context
Agregar headers comunes
Manejar autenticación
👉 Evita repetir código en cada dominio.

📄 authClient.ts
Maneja autenticación.
Puede:
Generar token
Refrescar token
Manejar login API

🗄 core/db/
📄 dbClient.ts
Conexión a base de datos.
Permite:
Ejecutar consultas
Validar persistencia
Confirmar procesamiento de eventos
📄 queries.ts
Centraliza queries reutilizables.
Ejemplo:
Consulta factura por ID
Validar estado de orden

📑 core/contracts/
📄 schemaValidator.ts
Valida JSON contra schemas.
Usa librerías como AJV.
👉 Mitiga cambios estructurales inesperados.

📁 schemas/
Contiene los contratos JSON.
Ejemplo:
factura.schema.json
promocion.schema.json

🛠 core/utils/
📄 helpers.ts
Funciones auxiliares genéricas.
Ejemplo:
Formatear fecha
Parsear datos
Validaciones comunes

📄 waitUtils.ts
Manejo de esperas personalizadas.
Ejemplo:
Esperar procesamiento asíncrono
Polling de estado

📄 dataGenerator.ts
Genera datos dinámicos.
Ejemplo:
IDs únicos
Emails aleatorios
Nombres dinámicos
👉 Reduce colisiones en ejecución paralela.

🧩 core/fixtures/
Extiende Playwright.
📄 baseFixture.ts
Define fixtures comunes:
Usuario autenticado
Configuración compartida
Setup por prueba
📄 authFixture.ts
Fixture específica para autenticación.
Permite:
Ejecutar pruebas ya logueadas
Reducir repetición de login

📊 core/test-data/
Datos globales reutilizables.
📄 users.data.ts
Usuarios estándar del sistema.
📄 roles.data.ts
Roles definidos (admin, supervisor, etc.)
📄 global.data.ts
Configuraciones comunes globales.

🏢 domains/ — Organización por Dominio
Cada carpeta representa un módulo funcional.
Ejemplo:
finanzas
compras
ventas
Cada célula es dueña de su dominio.

📁 domains/finanzas/
📁 api/
Pruebas de servicios REST.
Ejemplo:
crear-factura.spec.ts
cancelar-factura.spec.ts
📁 events/
Validación de procesamiento asíncrono.
Ejemplo:
factura.event.spec.ts
📁 ui/
Pruebas E2E del módulo.
Ejemplo:
flujo-facturacion.spec.ts
📁 pages/
Page Object Model del módulo.
Ejemplo:
FacturaPage.ts
📁 services/
Capa intermedia para llamadas API del dominio.
Evita poner request directo en los tests.
📁 test-data/
Datos específicos del dominio.
Ejemplo:
facturas.data.ts
clientes.data.ts

📊 reports/
Contiene:
HTML reports
Videos
Screenshots
Traces
Se genera automáticamente.

🚀 pipelines/
Contiene configuración CI/CD.

📄 azure-pipeline.yml
Define:
Instalación dependencias
Instalación navegadores
Ejecución por etiquetas
Publicación de reportes

✅ Resumen Estratégico
| Nivel | Responsabilidad |
|-------|-----------------|
| Root | Configuración general |
| core | Reutilizable transversal |
| domains | Pruebas por módulo |
| reports | Evidencias |
| pipelines | Automatización CI/CD |
